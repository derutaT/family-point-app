## Day/Week ビュー

### 目的
新規「きろく」タブで、獲得View / 使用View の対称形により日次・週次の分量を振り返れるようにする（spec 4.2 / ADR-0010）。両View共通の要求は「①総量が見える ②内訳が区別できる」。比較ビュー(4.3)の基盤も兼ねる。単体表示だけで価値が出る。

### 合意事項（2026-07-24 ユーザー確認済み）
- イベント記録は**新規モデル**で設計し、既存 `history` を廃止・置き換える（データ移行なし。ADR-0003）。
- 記録対象: 獲得4種（日替わり付与 / タスク即時 / タスク承認 / 手動調整）＋ 使用1種（あそび）。失効は記録しない（ADR-0011）。
- あそびイベントは「項目名」「利用時間」を持つ。「実測時間」の旧称は廃止（外部計測と紛らわしい）。
- 将来タイマーの一時停止・途中キャンセル実装で「購入時間 ≠ 実際の時間」となり得る前提で設計する。
- 日替わりは獲得の一部として同じViewに含め、内訳の区別で努力を読み取れるようにする（独立系列・非表示は却下。ADR-0010）。
- UI: 新規「きろく」タブ。子供ページは本人の記録、親ページにも同等ビュー（子供切替付き）。
- 日付境界は既存の朝5時、週は月曜起点。

### 実装ステップ
- [ ] S1: 新規イベントモデル設計（スキーマ・type 体系。overview §5 準拠）＋ 残高更新とイベント追記を1か所で行う関数の導入（T_001）
- [ ] S2: 全取引ポイント（日替わり付与 / 即時タスク / 承認 / 手動調整 / あそび）を S1 の関数経由に置き換え。あそびに項目名・利用時間を記録（T_001+T_002）
- [ ] S3: 既存 `history` の廃止。「使った記録 / ためた記録」画面を新モデル読みに書き換え（T_001）
- [ ] S4: Day/Week 集計関数と「きろく」タブ UI（獲得/使用切替・Day/Week切替・総量＋内訳）。Dayは明細リスト＋合計、Weekは日別サマリ＋内訳を基本に、ブラウザで見ながら調整（T_003）
- [ ] S5: 親ページへの同等ビュー導線（子供切替付き）（T_003）
- [ ] 各ステップ後にブラウザで動作確認（開発ルール）

### 完了の目安
子供 × 日 / 週 で獲得・使用が総量＋内訳で一覧でき、単体で「今日 / 今週どれだけ遊んだ・稼いだ・何で稼いだか」が分かる。

## スクリーンタイム解析くん（PoC 先行）

### 目的
iPad ScreenTime / みまもりSwitch のスクショから、アプリが取り込める Activity データ（overview §6）を生成する外部ツール。

### 不確実性 / PoC の狙い
最大の不確実性は「スクショから AI が安定して構造化できるか」。アプリと切り離して先に検証する（ADR-0007）。

### PoC 成功条件
- 実物スクショ（source 別に各 1〜2 枚）から、overview §6 の JSON を安定して出力できる。
- `app / minutes / category / chargeable` の判別が実用精度。
- `childId` と端末名 / ユーザ名の対応が付けられる。

### 確定した範囲
- 出力契約 = overview §6 の Activity スキーマ（固定）。
- 解析はアプリ外（ADR-0004）。差し替え可能。

### 詰める（要展開）
- [ ] スクショ入力 → 解析プロンプト / 処理 → JSON 出力の PoC
- [ ] source 別（switch / screentime）レイアウト差の吸収
- [ ] 精度評価（手動正解との突き合わせ）
- [ ] 本実装可否の判断 → 可なら P1 インポート + P3 表示へ接続

### 完了の目安
PoC が実用精度に達し、本実装した解析くんの出力をアプリが取り込んで比較ビューに反映できる。
