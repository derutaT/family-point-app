## Day/Week ビュー

### 目的
記録（努力/遊び/外部計測）を種別フィルタで単体表示し、日次・週次の分量を振り返れるようにする（spec 4.2 振り返りビュー）。努力だけ／遊びだけ等を単独で見られることが価値の中心で、比較ビュー(4.3)の基盤も兼ねる。単体表示だけで価値が出る。

### 入口条件 / 最初の確認
- 現状 `state` の構造（履歴の有無）を確認する。→ 履歴なしなら F1 を先に。

### 確定した範囲
- 表示単位: Day / Week。
- 対象データ: 獲得（日替わり / タスク）・消費（遊び）。
- 遊びには項目名・実測時間を持たせる（F2）。

### 詰める（実装タスク・要展開）
- [ ] 現 `state` スキーマ調査と差分設計（→ ADR-0003: 現在値保持＋イベント記録の分離）
- [ ] 取引時に残高更新とイベント追記を1か所で行う関数（残高とログのズレ防止）
- [ ] Day/Week 集計関数とビュー UI
- [ ] （必要なら）既存データの移行 / 初期化方針

### 完了の目安
子供 × 日 / 週 で獲得・消費が一覧でき、単体で「今日 / 今週どれだけ遊んだ・稼いだ」が分かる。

## スクリーンタイム解析くん（PoC 先行）

### 目的
iPad ScreenTime / みまもりSwitch のスクショから、アプリが取り込める Activity データ（overview §6）を生成する外部ツール。

### 不確実性 / PoC の狙い
最大の不確実性は「スクショから AI が安定して構造化できるか」。アプリと切り離して先に検証する（ADR-0007）。

### PoC 成功条件
- 実物スクショ（source 別に各 1〜2 枚）から、overview §6 の JSON を安定して出力できる。
- `app / minutes / category / chargeable` の判別が実用精度。
- `childId` と端末名 / ユーザ名の対応が付けられる。

### 確定した範囲
- 出力契約 = overview §6 の Activity スキーマ（固定）。
- 解析はアプリ外（ADR-0004）。差し替え可能。

### 詰める（要展開）
- [ ] スクショ入力 → 解析プロンプト / 処理 → JSON 出力の PoC
- [ ] source 別（switch / screentime）レイアウト差の吸収
- [ ] 精度評価（手動正解との突き合わせ）
- [ ] 本実装可否の判断 → 可なら P1 インポート + P3 表示へ接続

### 完了の目安
PoC が実用精度に達し、本実装した解析くんの出力をアプリが取り込んで比較ビューに反映できる。

overview §6 の Activity スキーマが、解析くん（出力）とアプリ（入力）の契約。先に固定済みなので、両者はこれを参照して並行できる。
