# 仕様: 活動突き合わせ機能（活動ビュー & 外部突き合わせ）

> Keyword: `activity-reconciliation`｜関連: 横断定義 `docs/spec/overview.md` / 背景・価値 `docs/prd/` / 決定 `docs/adr/` / 計画 `docs/task_plan/` / タスク `TASKS.md`
>
> 本書は本機能**固有**の「何を・どう作るか」に絞る。記録名・データモデル・Activity スキーマなど横断定義は `overview.md`、なぜ作るか・価値・運用方針は PRD を参照。

## 1. 概要
「ポイントの記録（申告）」と「計測された記録（実測）」を **並べて表示し明らかな差異に気づく** ことで成立する機能。
アプリ自身は「こっそり遊び」を検知できない（定義上アプリ外）ため、検知をシステムに負わせない（ADR-0001 / ADR-0002）。

## 2. 比較の単位・対象
申告 vs 実測を公平に並べるための単位・前処理。閾値による未申告・超過の強調や検出は初期では行わない（ADR-0009。将来追加する場合の判定単位もここに準ずる）。
- v1 は **子供 × 日 の合計** で並べる。
- 比較対象は `chargeable: true` の Activity のみ（教育/連絡等の非課金利用は除外。除外しないと外部合計が常にアプリ記録を上回り、フェアに比べられない）。
- 項目（ゲーム）単位の照合は v2 以降。ただし「ポイントの記録」側の遊びイベントには「項目名」を記録しておき、後の拡張余地を残す（ADR-0005）。

## 3. childId マッピング
- スクショ上の端末名 / ユーザ名 → アプリの `childId` の対応表を持つ（Activity スキーマは overview §6）。

## 4. 主要フロー
### 4.1 取り込み
スクショ → （外部）AI解析 → Activity JSON → アプリにインポート（手動: 貼り付け / ファイル読み込み）。外部の合計は当日終了後に確定するため、通常は前日分を翌日に取り込む **事後レビュー** となる（リアルタイムではない）。

### 4.2 振り返りビュー（単体表示）＝「きろく」タブ
新規「きろく」タブとして提供する。**獲得View / 使用View の対称形**（ADR-0010）で、選んだ1種類だけを Day / Week の分量として表示する（M_002 以降は外部計測（実測）も系列に加わる）。
- 両View共通の要求: **①総量が見える ②内訳が区別できる**。
  - 獲得View: 獲得源（日替わり / 各タスク / 手動調整）を内訳で区別。日替わりも獲得の一部として同じViewに含める。
  - 使用View: 使用先（ごほうび項目と利用時間）を内訳で区別。
- 用途: 頑張りの承認（獲得の内訳）、遊び量の自覚（使用）。突き合わせを伴わない単独利用が前提。
- 集計軸は子供 × 日 / 週。日付境界は既存の朝5時、週は月曜起点。
- 子供ページのきろくタブは本人の記録。親ページにも同等ビュー（子供切替付き）を置く。
- 比較ビュー（4.3）の片側だけを見ている状態に相当するが、独立した見方として一級で提供する。

### 4.3 比較ビュー（並列表示）
選んだ2系列を子供 × 日 / 週 で並置して見比べる。**システムは差を強調・判定しない**（ADR-0009）。気づきは子供に委ねる。
- **遊び申告 vs 外部計測**: 申告と実測を並べて見せる（対象は `chargeable` 合計, §2）。実測が申告を上回っていれば子供が自分で気づき、必要なら自己申告（4.4）できる。未申告・超過のフラグ付けや強調は初期では行わない（将来検討。ADR-0009）。
- **遊び vs 努力（生活バランス）**: 消費と獲得を並置し、偏り（遊んでばかり / 頑張りすぎ）への気づきを得る。
- 上記以外の2系列も同様に並置できる。

### 4.4 自己申告
比較ビューから子供がワンタップで遡及消費（不足分のポイント消費）を実行できる。「正直に申告した」事実は親子に見える形で残す（点数の報酬は付けない。ADR-0006）。

## 5. 経済ルール
- **借金（負残高）**: 現状は紙に記載し、子供がアプリで即時消費して返済する運用。アプリ内借金モデル化（T_004）は後段。当面は現運用を維持する。
- **段階返済**: 自己申告 = 1倍 / 使い過ぎ = 1倍 / 禁止を破ってバレた = 2倍。正直のインセンティブ設計（報酬を置かない方針）は PRD / ADR-0006 を参照。

## 6. 前提・制約・未解決
- 前提: ScreenTime / みまもりSwitch に Webアプリから読める公式エクスポート API は無い（**要再確認**）。よって取り込みはスクショ + AI解析 + 手動インポートを基本とする。
- 制約: localStorage 約5MB。長期運用ではイベントのロールアップが要る（この前提の見直し条件は ADR-0004）。
- **現状把握（確定）**: 現 `state` は **残高中心＋ `history` で部分的な取引履歴**（redeem/auto/approve）を持つ。日替わり付与は未記録で、残高が真実の源（overview §2）。
- **決定済み（2026-07-24）**: イベント記録は既存 `history` を流用せず**新規モデルで設計して置き換える**（データ移行なし。残高は保持のまま。ADR-0003）。日替わりの失効は記録しない（ADR-0011）。
